# Редизайн интерфейса

Живой документ работы над новым дизайном. Здесь — зафиксированные решения,
инвентарь экранов и статус. Макеты приходят порциями скриншотами; по мере
разбора каждой порции этот файл дополняется.

---

## Зафиксированные решения

| Вопрос | Решение |
|--------|---------|
| Глубина изменений | **Дизайн меняется полностью, вместе с перекомпоновкой.** Текущее расположение блоков (нижняя панель, выезжающая слева карточка, вертикальный тулбар) — не ограничение, перекладываем как на макетах |
| Тёмная тема | **Не нужна.** Делаем одну светлую. Существующие огрызки `prefers-color-scheme` в двух модалках — убрать, чтобы не разъезжалось |
| Адаптив | **Пока не нужен.** Целевая среда — десктоп. Верстать так, чтобы не рассыпалось при сужении, но отдельной мобильной раскладки не делаем |
| Айдентика | **Подбираем по скринам.** Готовой палитры, шрифта и логотипа нет — извлекаем из макетов и фиксируем в токенах |
| Технология стилей | **Остаёмся на CSS-модулях.** Без Tailwind и UI-китов. Общий слой — CSS-переменные в глобальном файле |
| Демо-данные | Пользователь даёт реальные графы JSON — на них проверяем холст |

---

## Порядок работы

1. Пользователь присылает порцию скриншотов макета.
2. Разбираем: что за экран, какие состояния, что меняется в поведении.
   Непонятное по функционалу — уточняем до начала работы.
3. Правим код, прогоняем `npm run typecheck`, снимаем скриншот результата.
4. Коммит в `develop`. Мерж — **только по явному подтверждению пользователя.**

Первым делом — слой токенов (палитра, типографика, радиусы, тени, отступы),
потому что сейчас цвета зашиты в 25 CSS-модулей и правятся по одному.
Дальше — экран за экраном под макеты.

## Что в стилях сейчас (отправная точка)

- 25 CSS-модулей, ~3500 строк, **все цвета захардкожены**; CSS-переменных нет.
  Только «синих» четыре: `#2563eb`, `#007bff`, `#667eea`, `#2196f3`.
- **Шрифт не подключён** — рендерится системным. `"Inter"` упомянут в одном
  месте, но не загружается.
- Медиазапросов на всё приложение — 4, ширины зашиты (панель 600 px,
  `.formTextarea max-width: 542px`, контейнер 1400 px).
- Раскладка главной подогнана руками: `margin-top: 100px` у контейнера,
  холст `height: 80%` от `100vh`, у нижней панели `margin-top: -100px`.
  Сверху висит пустая полоса.
- Тёмная тема — два обрывка `prefers-color-scheme` в `save-graph-modal` и
  `sources-table-modal`.

## Окружение разработки

```bash
npm ci                  # yarn-релиз в репо не лежит, ставим npm (как в CI)
npm run dev             # http://127.0.0.1:5173/gpt-graph-client/
npm run typecheck       # tsc --noEmit по обоим конфигам
npm run lint
npm run build           # typecheck + vite build
```

Бэкенда (`VITE_API_URL`) локально нет — запросы к LLM не пройдут. Чтобы
увидеть холст с реальным графом, кладём сохранённый JSON в `sessionStorage`
под ключом `autosave-graph` в форме
`{ nodes, edges, leaf_nodes, has_more, prompt, sources }` и перезагружаем
страницу — `Flow.tsx` поднимет его из автосейва.

Деплой: пуш в `develop` → GitHub Actions → GitHub Pages.

## Разбор макетов

### Ограничения, заданные заказчиком

- **Узлы и связи на полотне пока не трогаем.** Продукты синие, преобразования
  оранжевые, альтернативы фиолетовые — как сейчас. Названия узлов на макетах
  сгенерированы и могут врать; тёмный узел «Сырая нефть» — артефакт генерации,
  такого стиля в продукте не будет.
- **Бейджи ГИСП подготовлены, но не наполняются.** Подключения к базе нет:
  узел рисует бейдж только при `data.gispProducers`, которого пока никто не
  выставляет. Счётчик «Подтверждено в ГИСП» честно показывает 0.
- **Тёмной темы нет**, адаптив не делаем, стили — CSS-модули.

### Каркас

| Зона | Что в ней |
|------|-----------|
| Шапка | Логотип, разделы «Граф» / «Библиотека», поиск по графу (⌘K), «Экспорт», справка, уведомления |
| Панель над холстом | Название графа (в его меню — легенда), «Только продукты», «Фокус» + меню охвата, «Промышленные данные», «Альтернативы», «Очистить» |
| Левый рельс | Создать граф, Граф, База данных, Закладки, История |
| Правый рельс холста | Курсор, рука, рамка выделения · добавить узел, сохранить |
| Нижняя строка | Счётчики по видимой области, масштаб, вписать в экран, состояние сохранения |

### Масштаб интерфейса

Типографическая шкала и габариты полос подняты примерно на 15% относительно
первой версии: на мониторах 2K интерфейс читался слишком мелко. Всё завязано
на токены (`--fs-*`, `--h-topbar`, `--w-rail`, `--h-control`), так что
следующая подгонка — тоже правка в одном файле.

### Закладки

Узел отмечается правым кликом на полотне, попадает в раздел «Закладки» с
типом и заметкой; клик по названию подводит камеру и выделяет узел, карандаш
правит заметку. Закладки живут в памяти сессии и привязаны к id узлов
текущего графа: смена графа их сбрасывает, удаление узла уносит его закладку.
В файл графа они пока не пишутся — для этого нужно поле в формате сейва.

### Библиотека

Слева список сохранённых графов: поиск, фильтр порядка, «…» с
переименованием и удалением, внизу общее число графов. Справа — карточка
выбранного: превью схемы, блок «О графе» со счётчиками (узлы, связи,
уровни) и вкладки «Источники» / «Промышленные данные» / «Объединить графы».

Выбор графа в списке **не трогает полотно** — он догружает файл, чтобы
показать сводку. На полотно граф попадает кнопкой «Открыть граф», она же
переводит на вкладку «Граф»; при несохранённых правках сначала спрашивает.

Объединение переиспользует ту же логику, что и загрузка из файла: она
вынесена из компонента загрузки в хук `useMergeGraph`.

**Чего нет на сервере.** Список отдаёт только имя и даты, поэтому счётчики,
превью и источники считаются из самого файла графа. Описание в блоке «О
графе» — это `meta.prompt`, то есть запрос, которым граф создавали:
отдельного поля описания и тегов в формате сейва пока нет, и редактировать
их некуда.

### Поведение полотна

- **Режим указателя** (правый рельс): «выбор» — клик открывает карточку и
  узлы двигаются; «рука» — только панорамирование, карточка не открывается;
  «рамка» — протяжка левой кнопкой выделяет область, меню по правому клику
  там не мешает выделению.
- **Карточка узла и панель раздела** делят одно место слева: открывшаяся
  карточка закрывает панель, панель сдвигает панель над холстом вправо.
- **Создание графа** затирает текущий. Если на полотне есть несохранённые
  правки, сначала спрашиваем: сохранить, не сохранять или отменить.
- **Открытие сохранённого графа** из «Библиотеки» переключает на вкладку
  «Граф» и, при несохранённых правках, сначала спрашивает про них.
- **Полотно не размонтируется** при переходе на «Библиотеку»: экран
  раздела ложится поверх него. Через роутер `Flow` пересоздавался, и на
  обратном монтировании поднимал граф из автосейва — из-за этого только что
  открытый сейв подменялся прежним графом, а камера улетала.

### Счётчики нижней строки

Считаются **по видимой области**, а не по всему графу, и пересчитываются с
задержкой 120 мс после движения камеры. «Длина цепочек» — самая длинная
цепочка в кадре, в продуктах: преобразования это переходы, а не шаги.

### Карточка узла

Шапка: иконка-аватар (пробирка у продукта, шестерёнка у технологии),
название — правится прямо в шапке, бейдж типа, короткий ID, «…» и крестик.

Вкладки: «Краткое описание» / «Технологическое описание» / третья — у
продукта «Промышленные данные», у преобразования «Технологические маршруты».

«Краткое описание»: сворачиваемые блоки «Описание» (с кнопкой
«Редактировать»), «Связанные продукты» и «Источники» (со своим поиском и
таблицей), между ними — кнопка «Построить шаг».

У преобразования в «Кратком описании» есть ещё блок «Ключевая информация» —
параметры карточки технологии (оборудование, условия, ограничения). Они
приходят тем же запросом, что и технологическое описание, но читаются здесь.

«Технологическое описание» одинаково у продукта и преобразования: кнопка
«Изменить промпт» раскрывает настройки — поля карточки чекбоксами в две
колонки, выбор модели, системный промпт со счётчиком символов и тумблер
веб-поиска; ниже «Сбросить к шаблону» и «Получить описание».

У альтернативы своя раскладка: фиолетовая пробирка, бейдж «Альтернатива»,
единственная вкладка «Краткое описание» — ни карточки технологии, ни
обобщения шага у неё нет.

Длинные названия в шапке переносятся на следующую строку: поле названия —
многострочное, с подгонкой высоты под содержимое.

«Промышленные данные» — заглушка до подключения ГИСП.

**ID узла.** В данных у узлов UUID; в шапке показываем `prod_580627` —
префикс по типу плюс первые шесть знаков настоящего id. Это не выдуманный
номер и не номер из какого-либо реестра.

Модалки построения шага остаются как есть до отдельного макета.
