# e2e-site — проверка сайта в браузере

Один скрипт поднимает headless Chromium, отдаёт свежую сборку клиента на
`http://localhost:5199` и пересылает `/api/*` на боевой сервер
`https://sorangptgraph.xyz`. Сценарии печатают проверки `✔`/`✘`, в конце —
итог, статистика запросов и пути к скриншотам. Скрипты Playwright заново не
пиши: добавь сценарий сюда (см. ниже).

```bash
node .claude/skills/e2e-site/scripts/e2e.cjs --out=<папка для скриншотов> smoke step-down
node .claude/skills/e2e-site/scripts/e2e.cjs --list
```

Запускать из корня репозитория клиента. Код выхода: 0 — все проверки
прошли, 1 — есть провалы, 2 — сценарий упал (скриншот `<сценарий>-crash.png`).
Скриншоты по умолчанию — во временной папке; чтобы их увидел владелец,
передай `--out` в scratchpad или в рабочую папку.

## Сценарии

| Сценарий | Что проверяет | Время |
|---|---|---|
| `smoke` | приложение открывается, библиотека отвечает | ~5 с |
| `open-graph` | граф из библиотеки открывается (`GRAPH=часть названия`) | ~10 с |
| `perf` | большой граф на 50 %: курсор по графу без пауз, подсветка цепочки включается/гаснет и дёшева, перетаскивание (мс на шаг, кадры) | ~25 с |
| `card-race` | закрыть карточку и сразу щёлкнуть другой узел — карточка не пустая | ~25 с |
| `step-down` | ручной граф «Фенол» → шаг вниз: превью (раскрываемый продукт, второе сырьё), шаг на полотне, 4 альтернативы без наложений, «2 шага» | ~15 с |

По умолчанию большой граф — «ГК Титан Медицина+Нефтехимия+Смазочные+Сельское
хозяйство» (687 узлов) из библиотеки владельца; переименуют — передай
`GRAPH=…`. `perf` меряет в headless без видеокарты: абсолютные цифры хуже,
чем у пользователя, сравнивай прогоны между собой («было/стало» — тот же
сценарий на старой и новой версии).

Первый запуск собирает клиент (~30 с) в `node_modules/.e2e-site/dist`;
дальше сборка повторяется, только если менялись `src/`, `public/`,
`index.html`, `vite.config.ts` или `package-lock.json`.

## Флаги

| Флаг | Что делает |
|---|---|
| `--site=prod` | живой сайт вместо сборки — посмотреть, что видят пользователи, или снять «было» до выкладки |
| `--api=http://localhost:3001` | API — другой сервер (например, локальный из репозитория `server`) |
| `--live-model` | пропускать вызовы модели на сервер. **Стоит денег** — только по просьбе владельца; подставные ответы сценария при этом не используются |
| `--allow-writes` | разрешить запись на сервер (сохранение графов, закладки, история…). На боевом сервере — только по просьбе владельца |
| `--rebuild` / `--no-build` | пересобрать принудительно / не собирать |
| `--out=ПАПКА` | куда класть скриншоты |
| `--timeout=СЕК` | предел на сценарий (по умолчанию 240) |

Без флагов вызовы модели (`POST /api/graphs/gpt…`, расчёт баланса) получают
подставной ответ сценария или 503, а запись (`/api/graph-files`, ссылки,
загрузка документов…) — 403. В итоге видно, что именно было заблокировано:
если сценарию это мешает, реши, нужен ли флаг, и спроси владельца.

## Как докладывать
Владельцу хватает итога: сколько проверок прошло, что упало (с текстом
проверки), заметные цифры `perf`, 1–2 скриншота по делу. Логи целиком не
пересказывай.

## Новый сценарий
Файл `scenarios/<имя>.cjs`:

```js
module.exports = {
  description: "Что проверяет — одной строкой (видно в --list)",
  // необязательно: подставные ответы модели, путь → файл в fixtures/
  canned: { "/api/graphs/gpt/step/build": "fixtures/….json" },
  async run({ page, origin, env, lib, log, check, shot }) {
    await lib.openApp(page, origin);
    // …действия…
    check("что должно быть верно", условие, "подробность для отчёта");
    await shot("имя"); // скриншот <сценарий>-имя.png
  },
};
```

Готовые действия — в `scripts/lib.cjs`: `openApp`, `openLibraryGraph`,
`newManualGraph`, `stepDownToPreview`, `nodeBoxes` + `overlaps`, `nodeNear`,
`wheelZoom`, `measure` (кадры и длинные задачи за время действия). Поменялась
подпись кнопки — правь селектор в `lib.cjs`, а не в сценариях.

Подставной ответ модели — это настоящий ответ сервера, сохранённый из живого
прогона: запусти сценарий с `--live-model` (по согласованию), сохрани тело
ответа нужного запроса в `fixtures/` и пропиши его в `canned`.

## Если не работает
- `Cannot find module 'playwright'` — скилл рассчитан на облачную среду
  Claude Code, где Playwright и Chromium уже стоят. Локально:
  `npm i -D playwright && npx playwright install chromium`.
- Сайт или API не открываются — в настройках среды должен быть разрешён
  доступ к `sorangptgraph.xyz`.
- `К источникам из базы` не найдена в `step-down` — у «Фенола» на сервере
  пропали источники из базы; выбери другой продукт и подставные ответы.
