# Граф производства — клиент

Веб-приложение для построения производственных цепочек: продукты и
преобразования между ними на полотне, шаги строит модель (Qwen через наш
сервер, репозиторий `PePorMAty/server`). Стек: React 19, TypeScript, Vite,
Redux Toolkit, `@xyflow/react` (React Flow 12).

## Владелец и порядок работы
- Общаемся по-русски, дружелюбно, с объяснением, что и зачем делаем.
- **Ничего не мержить без подтверждения владельца.** PR — только по просьбе.
- `develop` — то, что на сайте; `mvp` — ступень перед ним. Эти ветки не
  трогать и не пушить в них: работа идёт в своей ветке, владелец сам
  сливает её по цепочке ветка → `mvp` → `develop`.
- Общая рабочая ветка — `claude/combined-testing` (в ней слиты
  `claude/cloud-product-testing-cg98tm` и `claude/beautiful-hamilton-4whfax`);
  новую работу начинай от неё, чтобы ветки не расходились.
- Выкладка (делает владелец): GitHub Pages собирается workflow'ом при пуше в
  `develop`; свой домен https://sorangptgraph.xyz — `deploy/deploy-site.sh`
  (см. `deploy/DEPLOY.md`). Для проверки до слияния владелец может выложить
  на домен и рабочую ветку (`deploy-site.sh <ветка>`); что сейчас на домене —
  `https://sorangptgraph.xyz/version.txt`.

## Команды
- `npm run typecheck`, `npm run lint`, `npm run build` (сборка включает typecheck).
- `npm test` — Vitest, `src/**/*.test.ts`: материальный баланс, раскладка
  шага на полотне, склонения. Меняешь расчёт или раскладку — добавь случай.
- У `lint` есть старый фон: 1 ошибка в
  `src/components/upload-graph/MergeReportModal.tsx`
  (react-refresh/only-export-components) и ~17 предупреждений — сравнивай
  с ним, а не с нулём.
- Переменные сборки: `VITE_API_URL` (база API, на сайте `/api`), `VITE_BASE`
  (`/` для своего домена; без неё — `/gpt-graph-client/` для Pages).

## Проверка в браузере
Скилл `e2e-site` (`.claude/skills/e2e-site/`): свежая сборка в headless
Chromium, API — боевой сервер; запись на сервер и вызовы модели по
умолчанию выключены. Сценарии: открыть граф, замер скорости на большом
графе, быстрый переход между карточками, шаг «вниз» на подставных ответах
модели, цепочка вниз с балансом и техописанием (`phenol-chain`: живая модель
по просьбе владельца или бесплатно — `REPLAY` сохранённого прогона; с
`--server-repo` — промпты и разбор шага серверной ветки до выкладки).
Пользуйся им, а не пиши скрипты Playwright заново. Нужен только
итог (было/стало, перед отчётом) — отдай прогон агенту `site-tester`
(`.claude/agents/site-tester.md`): он запустит скилл в своём контексте и
вернёт 10 строк.

## Карта кода
- `src/Flow.tsx` — полотно (большой компонент: узлы/связи для React Flow,
  карточка, режимы). Строка состояния и мини-карта —
  `src/components/status-bar/`, `src/components/canvas-minimap/`.
- `src/store/slices/gptSlice.ts` — граф и шаги; `src/store/api/*` — запросы
  к серверу; `src/store/graphExtras.ts` — закладки, история, расчёты баланса
  и идентификаторы рядом с сохранённым графом.
- `src/components/flow-panel/` — карточка узла, мастер шага, превью шага.
- `src/utils/stepToFlow.ts` — как шаг ложится на полотно;
  `src/utils/materialBalance.ts` — материальный баланс (см. `MATERIAL-BALANCE.md`).
- `src/docs/user-guide.md` — руководство пользователя, открывается в
  приложении: меняешь поведение интерфейса — поправь и его.

## Как здесь пишут код
- Комментарии и тексты интерфейса — по-русски; комментарий объясняет,
  почему так, а не что делает строка.
- Числа с подписью — через `src/utils/plural.ts` («1 шаг», «3 шага»).
- Боевой сервер может отставать от серверной ветки: новый эндпоинт, которого
  там ещё нет (404), не должен ломать клиент — работаем как раньше.
- На графах в сотни узлов (в библиотеке есть граф на 687) не пересобирай
  все узлы и связи на частые события вроде наведения: React Flow
  перерисует каждый.
